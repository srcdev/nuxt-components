    Methodology: "Styling doc", "Tests", "Story" and "Variants folder" are filesystem checks (CONSUMER-STYLING.md, a tests/ dir, a stories/ dir or *.stories.ts file, a variants/ subfolder). "Skill doc" and "Snippet" match the component's kebab-case name against .claude/skills/components/*.md and .vscode/*.code-snippets — a small number of near-miss names may read as false negatives and are worth a manual glance before acting. "Score" is the count of the five doc/test/story/skill/snippet checks passed, out of 5, and is what "reference-quality" and "only incomplete" are based on.

    On --_ vars: the public/private split is decided by consumer relevance, not reuse count — a private var is correct even used once, as long as the value has no plausible consumer override. This column is a raw count of --_-prefixed CSS custom properties per group; it is not scored and doesn't factor into "reference-quality" or "score." A high count is only a prompt to check each one by hand for a value that should have been public (a colour, size, or per-state variant with no override token) — the bug class the ServicesCard fix (CLAUDE.md pitfall #20) caught, not the presence of the prefix itself.
